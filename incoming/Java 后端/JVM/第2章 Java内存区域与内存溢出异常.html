第2章 Java内存区域与内存溢出异常
  • 2.1 概述
    • Java和C、C++不一样，C、C++的开发人员要自己掌握每一个对象从出生到终结的责任，而Java程序员在虚拟机自动内存管理机制的帮助下，不需要为每一个new操作去写配对的delete/free代码，不容易出现内存泄露和溢出的问题。但是Java程序员也得懂虚拟机是怎么使用内存的，不然出现内存泄露和溢出的问题就炸了。本章介绍的是Java虚拟机内存的各个区域及其的作用、服务对象和可能出现的问题。
  • 2.2 运行时数据区域
    • Java虚拟机在执行Java程序时会把他管理的内存分成不同的区域，这些区域有各自的用途，以及创建和销毁的时间。
    • 2.2.1 程序计数器
      • 可看成当前线程所执行的字节码的行号指示器，字节码解释器通过改变这个计数器的值来选取下一条需要执行的字节码指令
        线程是CPU执行任务的最小单位，比如启动音乐播放器这个软件，是启动了一个进程。而在这个进程内部，音乐的播放、界面的响应等多个任务，是有不同的线程来分工完成的。
      • 线程私有。在任何一个时刻，一个内核只能执行一条线程上的指令，Java虚拟机的多线程是通过线程轮流切换、分配处理器执行时间的方式来实现的，因此为了线程切换后能恢复到正确的执行位置，每条线程都有独立的程序计数器
      • 是一块较小的内存空间，是唯 一一个在Java虚拟机规范中没有规定任何OutOfMemoryError情况的区域。
    • 2.2.2 Java虚拟机栈
      • 线程私有的，生命周期与线程相同
      • 描述的是Java方法执行的内存模型：JVM为每一个线程分配一个它自己私有的虚拟机栈
        因为程序是从 main 方法开始执行的，所以这个线程就是 main 线程，图里画的 main 线程栈就是 main 线程专属的那个虚拟机栈
        • 存放什么：在虚拟机栈里，每调用一次方法，就创建一个栈帧。栈帧里存放着
          main 方法被调用，创建 main 栈帧。 main 方法调用 method1，创建 method1 栈帧，并压在 main 栈帧 之上。 method1 方法调用 method2，创建 method2 栈帧，并压在 method1 栈帧 之上。 当 method2 执行完毕返回时，method2 栈帧 就会被弹出（销毁），以此类推。
          • 局部变量表：方法内部定义的变量（如int a = 10；）
          • 操作数栈：一个临时的计算空间，用于执行指令
          • 方法出口信息：方法执行完毕后应该返回到哪里
          • 存放单位为局部变量槽，局部变量表（即变量槽的数量）在方法编译时便确定且运行期间不会改变
      • 两类异常：（1）StackOverflowError异常：线程请求的栈深度大于虚拟机允许的深度 （2）OutOfMemoryError异常：没足够的内存申请栈扩展
    • 2.2.3 本地方法栈
      • 与虚拟机栈作用类似，区别为本地方法栈为虚拟机使用到的本地（Native）方法服务，而虚拟机栈为虚拟机执行Java方法（也就是字节码）服务
      • 同样两类异常：（1）StackOverflowError异常：线程请求的栈深度大于虚拟机允许的深度 （2）OutOfMemoryError异常：没足够的内存申请栈扩展
    • 2.2.4 Java堆
      • 线程共享，在虚拟机启动时创建，不过也可以划分出多个线程私有的分配缓冲器提升效率
      • 存放所有的对象实例和数组
      • 物理上可以不连续，但逻辑上连续
      • 可设置为固定大小的或可扩展的（-Xms和-Xms）
      • OutOfMemoryError异常：堆没内存了且不能扩展
    • 2.2.5 方法区
      • 线程共享
      • 方法区是 "静态"的蓝图，而虚拟机栈是 "动态"的执行过程
      • 用于存储已被虚拟机加载的类的信息
        • 存放什么：
          • 类信息：每个类的结构信息，比如它的字段、方法、构造函数等
          • 静态变量：用static修饰的变量，跟类绑定的
          • 常量：如final，字符串常量
          • 即时编译器编译后的代码缓存
      • 以前就是用永久代实现，现在用本地内存的元空间
      • OutOfMemoryError异常：方法区无法满足新的内存分配
    • 2.2.6 运行时常量池
      • 方法区的一部分：class文件中有一个常量池表，记录着字面量和符号引用，类加载后这些信息存放在方法区的运行时常量池中
        • 字面量：代码里写死的固定值。如String s = “你好”里面的“你好”，int a = 100；里的100
        • 符号引用：就是一些描述。如System.out.println只是个对“在System.out这个类里找println这个方法”的描述，是个代号没有具体在哪
          但是，system.out.println(s)的s不是符号引用，是局部变量，在虚拟机栈的局部变量表里
        • 直接引用：内存的真实地址。
      • 特点：
        • 把符号引用变为直接引用
        • 动态的，可以随时加入新产生的常量到常量池中，如String.intern()可以加入新的字符串
      • class文件格式是固定的，但运行时常量池的实现由厂商决定
      • OutOfMemoryError异常：常量池无法申请到新的内存
    • 2.2.7 直接内存
      • 不是虚拟机运行时数据区的一部分，不受JVM管理，是JVM向操作系统申请的一块区域，用来提高性能
        JVM派DirectByteBuffer对象直接在此区域操作数据，省去数据在系统内存和Java堆内存的搬运
      • OutOfMemoryError异常：申请太多了系统内存都不够了，这时候就不能分配新的直接内存了，程序也会因内存不足崩溃
  • 2.3 HotSpot虚拟机对象探秘
  • 要限定在具体的虚拟机和某个内存区域才有意义
    • 2.3.1 对象的创建
      • 1. 检查这个类是否已被加载、解析和初始化过，如果没有就先执行相应的类加载过程
      • 2. 为新生对象分配内存
        • 对象所需内存的大小在类加载完成后便可确定
          • 如果内存是规整的，那么只需把指针往空闲区域挪一段与对象大小相同的距离，这叫指针碰撞
          • 如果不规整，就用空闲列表记录哪些内存块是可用的
        • 要考虑线程安全
          • 同步
          • 本地线程分配缓冲：每个线程在Java堆中预先分配一小块内存，哪个线程要分配先在自己的本地缓冲区分配，不够用了分配新的缓冲区才同步锁定
      • 3. 初始化为零值（不包括对象头）
      • 4. 执行构造函数对对象初始化
    • 2.3.2 对象的内存布局
      • 对象头
        • Mark Word，存储对象自身运行时的数据，是个动态的数据结构
        • 类型指针，即对象指向它类型元数据的指针，用于确定是哪个类的实例。如果是数组，还有记录数组长度的数据
      • 实例数据
        • 真正存储的有效数据，父类继承下来的和子类定义的字段都要记录
      • 对齐填充
        • 占位符作用，如果实例数据不是8字节的整数倍的话用对齐填充补全，不是必须存在的
    • 2.3.3 对象的访问定位
      • 句柄访问
        • reference存的是对象的句柄地址，而句柄有到对象实例数据的指针和到对象类型数据的指针，对象实例数据存到Java堆中的实例池，对象类型数据存在方法区里
          对象实例数据：对象自己的数据，如p1：name = “张三”，age= 25 对象类型数据：类的描述信息，如Person类有哪些字段（name，age）、方法和它的父类是谁
        • 优点：只需要改变句柄的地址，reference不变
        • 缺点：多一步中转，慢
      • 直接指针访问
        • reference存的是对象地址，对象中包含实例数据和到对象类型数据的指针
        • 优点：快，HotSpot默认就是直接指针访问
        • 缺点：改的麻烦
  • 2.4 实战：OutOfMemoryError异常
    • 2.4.1 Java堆溢出
      堆的最小值-Xms参数和最大值-Xmx参数设置为一样避免堆自动扩展
      • 确认时内存泄露还是内存溢出
        • 内存泄漏：找到泄露对象和哪些GC Roots相关联导致垃圾回收器无法收集它们
        • 内存溢出：对象都是有必要存活的，看看能不能优化来减少内存消耗
    • 2.4.2 虚拟机栈和本地方法栈溢出
      栈容量-Xss参数
      • HotSpot虚拟机不支持栈的动态扩展，所以只会因为栈容量不够容纳新的栈帧出现致StackOverflowError异常
        每个线程分配到的栈内存越大，可以建立的线程就越少
    • 2.4.3 方法区和运行时常量池溢出
      • 自JDK 7起，原本存放在永久代的字符串常量池被移至Java堆之中
        • JDK 6，intern()方法会把首次遇到的字符串实例复制到永久代的字符串常量池中存储，返回的也是永久代里面这个字符串实例的引用
        • JDK 7的intern()方法实现不需要再拷贝字符串的实例到永久代了，既然字符串常量池已经移到Java堆中，那只需在常量池里记录一下首次出现的实例引用即可
    • 2.4.4 本机直接内存溢出
      • 由直接内存导致的内存溢出，一个明显的特征是在Heap Dump文件中不会看见有什么明显的异常情况，如果发现内存溢出之后产生的Dump文件很小，而程序中又直接或间接使用了DirectMemory，那就可以考虑重点检查一下直接内存方面的原因了
