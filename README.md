# 个人技术知识库 — 支持幕布和思源笔记

已包含你的两篇示例：**幕布 HTML 导出的 JVM 笔记**，以及**思源 ZIP 导出的 MySQL 笔记**。

## 1. Windows 上怎么用

1. 将网站 ZIP 解压到一个单独文件夹（例如 `D:\TechBlog`）。
2. 在里面的 `incoming/` 文件夹中，按 Java/JVM、数据库/MySQL 等主题建立子文件夹。
3. 将 **幕布的 `.html` 或 `.opml`** 文件直接放进对应文件夹；将 **思源的 `.md.zip`** 文件直接放进去，无需解压。普通 `.md` 也支持。
4. 双击 `build.bat`；首次构建会安装 Python 依赖，需要电脑上有 Python 和网络。
5. 打开 `site/index.html` 浏览，左边有可展开的多级目录。代码高亮和 MathJax 公式支持均保留。

## 新版：支持搜索整篇笔记正文

- 左侧输入关键词，如 `MVCC`、`GC Roots`、`StackOverflowError` 或 `String.intern`，会从全部文章正文、标题、分类以及代码块中搜索。
- 搜索会展示匹配文章和正文片段；回车打开第一条结果，Esc 清空搜索。
- 构建时自动生成 `site/search-index.js`，无需数据库、在线搜索接口或者外部 JS CDN。**双击本地 `site/index.html` 也能全文搜索**。
- GitHub Pages / Cloudflare Pages / Netlify 发布后同样支持全文搜索。所有公开发布的文章内容都可由访问者读取，敏感笔记不要放入 `incoming`。

## 2. 图片到底怎么处理？

- 思源导出的 `.md.zip` 已包含 `assets` 文件夹，网页直接复用这些图片，不用下载。
- 幕布导出的 `.html` / `.opml` **只有幕布服务器的图片 URL，没有图片二进制文件**。
- 构建时会自动尝试从幕布服务器下载图片，成功后放到 `cached_images/` 并在网站文章的 `assets/` 中生成本地副本。
- 如果因网络、访问权限或图片 URL 失效而下载失败，终端会打印 `⚠ 图片缓存失败`。**这张图不会离线显示**；网页保留外链，联网时也许仍能显示，但不保证。
- 如果 Chrome/Edge 可以访问报错的图片链接，可把它另存为终端打印的 `cached_images/xxxxxxxx.png` 文件名，再次双击 `build.bat`。几十张图片成功自动缓存后就不用手工处理。
- 要上传 GitHub Pages 时，**把 `cached_images/` 也提交到仓库**，避免云端构建因无法访问幕布服务而丢图。

## 3. HTML、OPML 和第三方 Markdown，哪个优先？

- **最推荐直接用幕布导出的 `.html`**。新版构建脚本直接读取幕布特有的树形 HTML，保留多级大纲、加粗和备注。备注转换为引用段落，避免第三方转换器误判为代码块。
- `.opml` 也可作为来源，读取其树结构、富文本属性和图片地址。
- 第三方网站转换的 `.md` 文件可导入，但文件原本没有图片数据时，无法凭空恢复图片。
- 同一文件夹同时存在同名 HTML、OPML、Markdown 时，优先选择 HTML，避免文章重复。

## 4. 自动发布到 GitHub Pages

1. 在 GitHub 建立公开仓库，将此项目（包括 `.github/workflows/` 目录）提交至 `main`。
2. 在仓库 `Settings → Pages → Source` 选择 **GitHub Actions**。
3. Actions 会运行构建脚本并发布 `site/`。后续只需要更新 `incoming/` 和必要的 `cached_images/` 文件后提交。

注意：公开仓库内不要放敏感信息，正式投简历前请检查所有文章和图片在手机、无痕浏览器及国内网络环境下的访问情况。

## 新版：思源 Markdown 行内代码（Inline Code）

- 实测 `LeetCode Hot 100 笔记.md.zip` 中 `prev`、`cur`、`cur.next`、`next = cur.next → ...` 等 **120 个行内代码片段**，无需调整思源导出选项。
- 用细边框、浅灰背景、圆角和等宽字体渲染，适配浅色/深色主题；很长的片段可在手机端换行。
- 清理思源导出中紧贴反引号后的 U+200B 零宽空格，原 ZIP 不受影响。
- 三反引号多行代码块仍按 `java`、`python`、`text` 等语言独立渲染，Pygments 高亮不受影响。

### 升级旧博客

直接下载完整新版，将你以前积累的 `incoming/` 和 `cached_images/` 复制或合并到新版，运行 `build.bat`。若只想更新程序，替换 `build.py`、`templates/style.css` 即可（基于上次的全文搜索兼容版）。

## 图片不显示：修复说明（最新版）

- 在构建网站时检查每篇文章的本地图片路径，并将小于 12 MB 的 PNG/JPEG/GIF/WebP 图片直接嵌入 HTML 页面。**不会修改原 ZIP，也无需上传图床。**
- 思源导出的 `md.zip` 自带 `assets` 图片；这次即使单独移动文章 HTML，已经嵌入的图片仍可以显示。
- 构建窗口显示每篇文章“已内嵌 / 外链 / 资源缺失”的数量；如果图片确实未在 ZIP 内，脚本会明确提示。
- 幕布 HTML/OPML 的远程图片仍需要先下载。由于这些文件只有链接，下载失败时无法自动内嵌，构建窗口会保留对应的失败提示。
- 图片内嵌会使 HTML 文件变大，适用于你的个人笔记规模。极大的图片（超过 12MB）仍使用本地相对路径。

## 新增：幕布外链图片一键补救（浏览器辅助）

1. 先运行 `build.bat`：它会尝试把幕布 HTML/OPML 中的在线图片下载到 `cached_images/`。
2. 如果下载失败，博客根目录会自动生成 **`恢复幕布图片.html`**。双击打开，点 **「尝试批量下载并打包图片」**。
3. 成功后浏览器会保存 `mubu-images.zip`，将压缩包直接放进 `cached_images/` 文件夹（**不要解压**）。
4. 重新运行 `build.bat`，构建脚本会读取图片补充包并将图片内嵌到网页。成功后日志会显示「已内嵌」。
5. 如果浏览器也无法下载（如受跨域、登录或网络限制），恢复页面会列出失败的原图链接；网页也会显示「打开原图」入口。**这意味着外部服务器不可访问，不能保证自动恢复。**

此功能不改变幕布原始 HTML，也不需要通过第三方转 Markdown。
`恢复幕布图片.html` 生成在根目录，不会随 `site/` 一起发布。缓存图片要与代码一起保存，供 GitHub Actions 使用。


## 正文折叠（新增）

- 打开任何文章，正文顶部会出现 **全部展开 / 全部折叠**。
- 像思源笔记一样，有子项的多级列表旁显示小三角；单击可收起/展开该项下面的所有层级，其他节点不受影响。
- 标准 Markdown `##`、`###` 等章节标题也支持折叠（只折叠该标题范围内的内容）。
- 会尝试记住本篇文章的展开状态；浏览器禁用本地存储时仍可正常使用。
- 点击右侧文章目录中的章节链接，会自动打开相应的折叠节点。
- 原始 `incoming` 文件、代码、图片、公式、搜索和部署逻辑保持不变。

对于长期学习笔记，推荐先用“全部折叠”快速浏览大纲，再按需展开章节。
